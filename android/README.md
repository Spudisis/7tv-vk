# VK7TV — модуль для приложения ВКонтакте на Android

То же самое, что расширение для браузера, только внутри официального
приложения ВК: слова-коды в сообщениях заменяются на эмоуты 7TV, а в панели
ввода появляется своя кнопка с пикером.

Рут не нужен. Работает не только с официальным приложением, но и
со сторонними клиентами ВК — Sova, Kate и прочими: модуль не проверяет
имя пакета, приложение ты выбираешь сам при патче.

## Текущие версии

- **Установщик (патчер)** — v0.4.0
- **Модуль** — v0.6.2

Руками следить за ними не нужно: установщик обновляет себя сам и тянет
свежий модуль с GitHub перед каждым патчем. Номера здесь — ориентир на
момент правки README, актуальные всегда в
[релизах](https://github.com/Spudisis/7tv-vk/releases)
(теги `installer-v*` и `android-v*`).

## Как это работает

Android не даёт одному приложению лезть в процесс другого. Обходится это
через [LSPatch](https://github.com/JingMatrix/LSPatch): он дописывает
в APK ВКонтакте загрузчик, который на старте подтягивает модуль. Код
самого ВК при этом не вырезается и не меняется — приложение работает
как обычно, просто рядом с ним теперь живёт наш модуль.

Плата за это одна: у пропатченного APK другая подпись, а Android не
обновляет приложение подписью, отличной от исходной. Значит оригинальный
ВК придётся один раз удалить (переписка на сервере, но войти нужно заново),
а обновления самого ВК ставить вручную — прогнал новую версию через патч,
поставил. Минуты две раз в пару недель.

Всё обратимо: удалил пропатченный ВК, поставил обычный из Play Store —
и телефон как был.

Пропатченный APK нельзя раздавать другим. Это чужое приложение под твоей
подписью, по форме неотличимо от подсунутого фейкового клиента. Поэтому
установщик патчит ВК **на телефоне пользователя, из его же копии ВК** —
готовый пропатченный APK никуда не уезжает.

## Установка через установщик

Так проще всего. Нужен Android 9+ (API 28) — ради системного декодера
анимированных webp.

1. Скачать APK установщика (`vk7tv-installer-*.apk`) из
   [релизов](https://github.com/Spudisis/7tv-vk/releases) и поставить как
   обычное приложение. Первый раз Android попросит разрешить установку из
   этого источника — разрешить.
2. Открыть **VK7TV Установщик**, нажать на своём клиенте ВК «пропатчить».
3. Подтвердить два системных диалога: удаление оригинального ВК и установку
   пропатченного. Всё.

Что установщик делает сам:

- **тянет свежий модуль с GitHub** перед патчем — руками ничего скачивать
  не надо (если сети нет, берёт версию, вшитую в него при сборке);
- **обновляет себя** — при запуске проверяет, нет ли на GitHub установщика
  новее, и предлагает обновиться одной кнопкой;
- находит и официальный ВК, и сторонние клиенты (Sova, Kate) — а не нашёл,
  жми «Показать все приложения» и выбери вручную.

**Обновление модуля** потом — это тот же экран: у уже пропатченного клиента
кнопка называется «обновить модуль». Оригинал установщик достаёт из самого
пропатченного APK (LSPatch прячет его внутри), патчит заново свежим модулем
и ставит **поверх** — подпись та же, поэтому вход в аккаунт сохраняется,
заходить заново не нужно.

Ни Shizuku, ни беспроводной отладки, ни файловых менеджеров установщику
не требуется: ставит и удаляет APK через системный установщик пакетов,
пользователь только подтверждает диалоги.

## Установка вручную (без установщика)

Если не хочешь ставить установщик, можно собрать пропатченный APK сам:

1. Поставить [LSPatch](https://github.com/JingMatrix/LSPatch/releases)
   и APK модуля (`vk7tv-module-*.apk`) — оба как обычные приложения.
   Чтобы LSPatch сам ставил и удалял APK, ему нужен
   [Shizuku](https://shizuku.rikka.app/) (иначе итоговый APK ставишь руками).
2. В LSPatch: **+** → выбрать установленный ВКонтакте → **локальный режим**.
3. Пропатчить, удалить оригинальный ВК, поставить полученный APK.

Локальный режим важен: он подгружает модули из LSPatch на лету, поэтому
обновление модуля — это просто установка нового APK, **без перепатчивания
ВК**. Во встроенном режиме пришлось бы каждый раз заново.

## Настройки

**Долгий тап по круглой кнопке 7VK** внутри ВК. Там наборы, переключатели
и перенос настроек из браузерного расширения.

Отдельного приложения-настройки нет намеренно. Модуль встроен в чужой APK
и до данных своего приложения не дотягивается — `XSharedPreferences` там
не работает. Поэтому конфиг живёт в `SharedPreferences` самого ВК, и раз
он там, то там же и правится. Заодно доступен на запись, так что
избранное меняется прямо из пикера.

Перенести настройки из браузера: в попапе расширения «Резервная копия
настроек» → «Сохранить в файл», дальше открыть файл на телефоне,
скопировать целиком и вставить в поле импорта. Списки эмоутов оттуда
не берутся — модуль качает их с 7tv.io сам по id наборов, поэтому вы
с другом видите одинаковые картинки под одним словом.

При первом запуске, если наборов нет, подключается `bratishkinoff` —
как и в расширении. Одноразово: удалил из списка, сам не вернётся.

Наборы кэшируются на диск и живут там, пока не нажмёшь «Обновить наборы
с 7tv.io» в настройках. Проверять их при каждом запуске приложения —
это запрос к API на набор, а меняются они раз в месяц. Обратная сторона:
эмоуты, добавленные владельцем набора, приедут не сами.

## Предложение подключить набор

Если в чат прилетает слово вида `имя_ник`, а такого эмоута у тебя нет —
модуль проверяет по API, есть ли такой стример и лежит ли эмоут с таким
именем в его наборе. Сошлось — слово подсвечивается, а в пикере сверху
появляется строка «МОЖНО ПОДКЛЮЧИТЬ» с превью и количеством эмоутов.
Тап — набор подключается, и слово тут же становится картинкой.

Где проходит граница «эмоут | стример», заранее не понять: в `ok_bratishkinoff`
подчёркивание одно, а в `SEXALARM_kanba_mx` ник сам с подчёркиванием —
стример тут `kanba_mx`. Поэтому разделители перебираются слева направо
(не больше трёх), и берётся первый вариант, который сходится по API.
Имя сверяется с учётом регистра: подключим набор — эмоут должен
отрендериться ровно тем словом, которое пришло.

Ответы кэшируются, в том числе «не нашлось», плюс стоит потолок в 40
запросов на сессию: чат с сотней незнакомых слов не должен превращаться
в сотню обращений к API. Выключается в настройках, «Предлагать наборы
стримеров».

Само слово при этом показывается **картинкой того самого эмоута** — с
тонкой синей чертой снизу, чтобы не спутать его со своим. Картинки ещё нет
(качается) — остаётся подсвеченным словом; приедет — перерисуется. Больше
трёх картинок на сообщение не рисуем: чат с полусотней незнакомых кодов не
должен разом просить полсотни декодирований. Выключается отдельно —
«Показывать картинку предложения».

**Тап по слову открывает поповер** с превью, ником, количеством эмоутов и
кнопкой подключить (плюс крестик — не предлагать этот набор). В браузере
рядом со словом рисуется такой же чип.

Нажимаемым слово сделано не через `movementMethod` — он у чужого `TextView`
занят, через него ВК ловит ссылки и упоминания. Вместо этого цепляем
платформенный `TextView.onTouchEvent` (`Taps.kt`), так же как модуль уже
цепляет `setText`, и забираем себе только те касания, что пришлись
ровно в наше слово. Жест забирается целиком, с самого нажатия: `ViewGroup`
запоминает получателя по ответу на `ACTION_DOWN`, и половинчатый вариант
оставил бы ВК заведённый таймер долгого нажатия.

Съесть касание — только половина дела. Долгое нажатие ВК ловит не в самой
вьюхе, а выше: в `onInterceptTouchEvent` предка (у списка — через
`OnItemTouchListener`). Туда события приходят **раньше**, чем к нам, поэтому
наше «съел» его не останавливает — поверх поповера открывалось меню
сообщения. Лечится штатным `requestDisallowInterceptTouchEvent`: им ребёнок
и говорит родителям, что жест занят, а `RecyclerView` заодно пробрасывает
отказ своим `OnItemTouchListener`, и те гасят свои распознаватели.

Прокрутка списка при этом не ломается: как только палец поехал дальше
`scaledTouchSlop`, запрет снимается, и список забирает жест сам. Касания
мимо слова ВК получает так, будто нас здесь нет.

Плата одна: **на самом слове нет меню сообщения ВК**. Держать его там не
вышло — слово в строке маленькое, палец на нём задерживается, и обычный тап
регулярно переваливал за порог долгого нажатия. Поэтому нажатие на слово
всегда делает одно и то же, а меню сообщения живёт на всей остальной площади
пузыря. Если палец всё же задержался дольше порога, поповер не открывается
вовсе: запрет перехвата помогает не на всякой разметке, и одно чужое меню
лучше, чем два сразу.

## Как это выглядит

**В переписке.** Слово-код превращается в картинку прямо в строке, размер
привязан к размеру шрифта (1.8 высоты), так что при любом системном
масштабе текста эмоут остаётся в строке. Zero-width эмоуты накладываются
поверх предыдущего, пробел между ними съедается.

**Кнопка.** Круглая «7VK» в ряду иконок панели ввода, рядом со стикерами.
Если ряд опознать не удалось (ВК перекроил разметку) — модуль вешает
плавающую кнопку поверх экрана, её можно перетаскивать. Функциональность
важнее идеального места.

**Пикер.** Панель над строкой ввода, до 45% экрана, тёмная, той же
палитрой, что и поповер в браузере (`#1e1f24` / `#34363f` / `#4c8bf5`).
Именно над, а не поверх: иначе не видно, что вставилось в поле.

```
┌─────────────────────────────────┐
│ 7TV                           ✕ │
│ ┌─────────────────────────────┐ │
│ │ Поиск эмоута                │ │
│ └─────────────────────────────┘ │
│ ИЗБРАННОЕ                       │
│ [x][x][x][x][x][x] →            │
│ (Все)(Глобальные)(bratishkinoff)│
│ ┌─┬─┬─┬─┬─┬─┬─┐                 │
│ │ │ │ │ │ │ │ │                 │
│ ├─┼─┼─┼─┼─┼─┼─┤                 │
│ │ │ │ │ │ │ │ │   ↕ прокрутка   │
│ └─┴─┴─┴─┴─┴─┴─┘                 │
└─────────────────────────────────┘
```

Тап по эмоуту вставляет его **полное имя** (с постфиксом набора,
`ok_bratishkinoff`) в позицию курсора — как в веб-пикере, чтобы эмоут не
спутался с одноимённым из другого набора. **Долгий тап** — в избранное
и обратно.

Звёздочки в углу ячейки, как в вебе, здесь нет намеренно: на телефоне
в неё не попасть пальцем, а долгий тап — привычный жест.

Наборы сделаны чипами-фильтрами, а не заголовками секций: на телефоне
сетка узкая, и заголовки съедали бы половину высоты.

**Порядок вкладок меняется перетаскиванием**: зажми вкладку набора и веди
её вбок — соседи разъезжаются, у краёв лента подматывается сама. Отпустил —
порядок сохранился и переживёт перезапуск. Переставляются только свои
наборы; «Все», «Глобальные» и «Свои эмоуты» стоят на местах — за ними нет
набора, который можно было бы подвинуть. На порядок картинок это не влияет:
кому достанется голое имя эмоута, решает алфавит слагов, а не порядок
вкладок, — иначе у вас с другом под одним словом были бы разные картинки.

## Установщик

`installer/` — отдельное приложение (`com.vk7tv.installer`), которое патчит
ВК на телефоне, без Shizuku и без LSPatch-приложения. Внутри — консольный
патчер [LSPatch](https://github.com/JingMatrix/LSPatch) (`libs/lspatch.jar`,
GPL-3), вызванный как библиотека.

| Файл | Зачем |
|---|---|
| `MainActivity.kt` | экран на одну кнопку, машина состояний патча |
| `Vk.kt` | поиск клиентов ВК, добыча оригинальных APK (в т.ч. из пропатченного) |
| `Patcher.kt` | обёртка над `LSPatch` — вшивает модуль в APK ВК |
| `Installer.kt` | установка и удаление APK через `PackageInstaller` |
| `Releases.kt` | свежий модуль и обновление самого установщика с GitHub |
| `Http.kt` | скачивание без зависимостей |

Как это устроено:

- **Загрузчик LSPatch — это ресурсы класслоадера.** `LSPatch.java` читает
  `loader.dex`, `metaloader.dex`, четыре `liblspatch.so` и ключ подписи
  через `getResourceAsStream("assets/lspatch/…")`. Чтобы они оказались в APK
  установщика ровно по этим zip-путям, `lspatch.jar` подключён как
  `implementation(files(...))` — его `.dex` и ключ AGP кладёт как есть, а вот
  `.so` слияние java-ресурсов выкидывает (ждёт их в `lib/`). Поэтому четыре
  `liblspatch.so` мы достаём из jar отдельной gradle-задачей и кладём в
  Android-assets по тому же пути `assets/lspatch/so/<arch>/liblspatch.so`.
  **Нужны все четыре ABI**, а не только ARM: при патче LSPatch добавляет
  `liblspatch.so` под каждый ABI, который есть в оригинале ВК. «Универсальные»
  сборки ВК (ими и патчат) содержат `lib/x86` и `lib/x86_64` — убрать x86-`.so`
  из ассетов нельзя, иначе патч молча падает нативным крешем на «Патчу
  приложение ВК…». Сам `classes.dex` установщика (весь конвейер LSPatch, 10+ МБ)
  пакуем сжатым (`packaging.dex.useLegacyPackaging`) — установка чуть дольше,
  зато скачивание вдвое легче, что важно на слабом интернете.
- **Оригинал для перепатча брать неоткуда — и не надо.** LSPatch прячет
  исходный APK внутри пропатченного (`assets/lspatch/origin.apk`), поэтому
  «обновить модуль» = достать оттуда оригинал, пропатчить свежим модулем,
  поставить поверх. Свой архив ВК на 200 МБ хранить не нужно.
- **Первый патч ставится через удаление, обновление — поверх.** Оригинал
  подписан ключом ВК, патч — постоянным ключом LSPatch, поверх нельзя →
  удаляем оригинал. А два патча подписаны одним ключом → обновление встаёт
  поверх, вход в аккаунт сохраняется.
- **Модуль вшит в установщик как офлайн-запас** (`assets/module/module.apk`,
  копируется из сборки `:app`), но штатно тянется последний с GitHub.

Установщик — производная от LSPatch (GPL-3), поэтому и сам под GPL-3;
полный текст лицензии — `installer/LICENSE`.

## Устройство модуля

| Файл | Зачем |
|---|---|

| `Replacer.kt` | разбор текста на слова и сборка Spannable |
| `Spans.kt` | `EmoteSpan`, стопка zero-width, мост анимации во View |
| `Service.kt` | защита служебных подписей (время, «(ред.)») |
| `Emotes.kt` | реестр имён, загрузка наборов с 7tv.io |
| `EmoteCache.kt` | картинки: скачивание, диск, LRU, декод |

| `Net.kt` | HTTP из процесса ВК |
| `Inject.kt` | кнопка в панели ввода + плавающий запасной вариант |
| `PickerUi.kt` | панель пикера |
| `SettingsUi.kt` | настройки внутри ВК |
| `Config.kt` | конфиг в хранилище ВК |
| `SettingsActivity.kt` | экран-памятка, настроек в нём нет |

### Почему хук именно за `TextView.setText`

Классы ВК обфусцированы R8 и переименовываются от версии к версии — модуль,
завязанный на них, ломался бы каждое обновление. Платформенный `TextView`
стабилен, поэтому цепляемся за приватный
`setText(CharSequence, BufferType, boolean, int)`: через него `TextView`
прогоняет вообще все варианты `setText`, включая `setText(int)`.

Панель ввода ищется так же «снаружи»: находим `EditText`, поднимаемся на
пару уровней и берём ряд, где рядом с полем уже висят `ImageView`.

### Что сломает обновление ВК

Не факт обновления сам по себе, а переезд чата на Jetpack Compose: там
`TextView` не используется вообще, и хук перестанет что-либо находить —
молча, без крашей. На этот случай в модуле есть канарейка: через 30 секунд
после старта она пишет в журнал, сколько текстов прошло через хук
и сколько подмен сделано. Ноль подмен при живых наборах — повод смотреть,
что изменилось.

Если ВК начал падать — поставить обратно оригинальный APK из Play Store.
Все хуки обёрнуты в `try/catch` (`L.safe`), потому что неперехваченное
исключение в чужом процессе роняет не нас, а ВК.

## Сборка

```bash
export JAVA_HOME=/opt/homebrew/opt/openjdk@17
export ANDROID_HOME=/opt/homebrew/share/android-commandlinetools

# модуль
cd android && gradle :app:assembleDebug
# APK: app/build/outputs/apk/debug/app-debug.apk

# установщик (сам собирает и вшивает свежий модуль)
gradle :installer:assembleStableDebug
# APK: installer/build/outputs/apk/stable/debug/installer-stable-debug.apk

# пробный установщик — другой канал обновлений, см. ниже
gradle :installer:assembleDevDebug
```

## Пробные сборки

Иногда сборку нужно проверить до общего релиза — на паре устройств, а не
у всех сразу. Для этого у установщика два канала.

| | Тег модуля | Тег установщика | Пакет установщика | Имя в лаунчере |
|---|---|---|---|---|
| Обычный | `android-vX.Y.Z` | `installer-vX.Y.Z` | `com.vk7tv.installer` | VK7TV |
| Пробный | `android-dev-vX.Y.Z` | `installer-dev-vX.Y.Z` | `com.vk7tv.installer.dev` | VK7TV dev |

Пробные релизы публикуются с `--prerelease`. Обычный установщик их не
видит по двум независимым признакам сразу: и по флагу prerelease, и по
тегу (`installer-v…` не совпадает с `installer-dev-v…`). Забытая галочка
в вебе не должна разом высыпать пробные сборки всем.

У пробного установщика своё имя пакета, поэтому он **стоит рядом** с
обычным, а не поверх: тестировщик может держать оба. Себя он обновляет
только пробными релизами (обычный APK — это другое приложение, оно бы
встало рядом третьей иконкой), а модуль берёт самый свежий из доступных —
если пробного релиза модуля нет, возьмёт обычный.

Вшитый офлайн-запас модуля в обеих сборках один и тот же (`:app:assembleDebug`):
это резерв на случай «GitHub недоступен», а штатно модуль тянется с GitHub.
