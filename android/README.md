# VK7TV — модуль для приложения ВКонтакте на Android

То же самое, что расширение для браузера, только внутри официального
приложения ВК: слова-коды в сообщениях заменяются на эмоуты 7TV, а в панели
ввода появляется своя кнопка с пикером.

Это **модуль LSPosed** — отдельное приложение, которое цепляется к процессу
ВК. Сам APK ВКонтакте не трогается: он обновляется из Play Store как обычно,
модуль просто цепляется заново при следующем запуске.

## Что нужно

- root + Magisk
- [LSPosed](https://github.com/JingMatrix/LSPosed)
- Android 9+ (API 28) — ради системного декодера анимированных webp

## Установка

1. Собрать APK: `./gradlew assembleDebug` (см. «Сборка»)
2. Поставить его на телефон
3. В LSPosed включить модуль **VK7TV**, в области действия отметить
   «ВКонтакте» и/или «VK Мессенджер»
4. Принудительно остановить ВК и запустить снова
5. Открыть VK7TV, нажать «Импорт настроек из расширения» и скормить ему
   файл из попапа браузерного расширения («Резервная копия настроек» →
   «Сохранить в файл»)

Списки эмоутов в файле не лежат — модуль тянет их с 7tv.io сам, по id
наборов. Поэтому конфиг лёгкий, а картинки всегда свежие.

## Как это выглядит

**В переписке.** Ровно как в браузере: слово-код превращается в картинку
прямо в строке, размер привязан к размеру шрифта (1.8 высоты), так что при
любом системном масштабе текста эмоут остаётся в строке. Zero-width эмоуты
накладываются поверх предыдущего, пробел между ними съедается.

**Кнопка.** Круглая «7TV» в ряду иконок панели ввода, рядом со стикерами.
Если ряд опознать не удалось (ВК перекроил разметку) — модуль вешает
плавающую кнопку поверх экрана, её можно перетаскивать. Функциональность
важнее идеального места.

**Пикер.** Панель снизу на 45% экрана, тёмная, той же палитрой, что и
поповер в браузере (`#1e1f24` / `#34363f` / `#4c8bf5`):

```
┌─────────────────────────────────┐
│ 7TV                           ✕ │
│ ┌─────────────────────────────┐ │
│ │ Поиск эмоута                │ │
│ └─────────────────────────────┘ │
│ ИЗБРАННОЕ                       │
│ [x][x][x][x][x][x] →            │
│ (Все)(Глобальные)(bratishkinoff)│
│ ┌─┬─┬─┬─┬─┬─┬─┐                 │
│ │ │ │ │ │ │ │ │                 │
│ ├─┼─┼─┼─┼─┼─┼─┤                 │
│ │ │ │ │ │ │ │ │   ↕ прокрутка   │
│ └─┴─┴─┴─┴─┴─┴─┘                 │
└─────────────────────────────────┘
```

Тап по эмоуту вставляет его **полное имя** (с постфиксом набора,
`ok_bratishkinoff`) в позицию курсора — как в веб-пикере, чтобы эмоут не
спутался с одноимённым из другого набора. Долгий тап показывает имя.

## Устройство

| Файл | Зачем |
|---|---|
| `Vk7tvModule.kt` | точка входа, хук `TextView.setText`, канарейка |
| `Replacer.kt` | разбор текста на слова и сборка Spannable |
| `Spans.kt` | `EmoteSpan`, стопка zero-width, мост анимации во View |
| `Service.kt` | защита служебных подписей (время, «(ред.)») |
| `Emotes.kt` | реестр имён, загрузка наборов с 7tv.io |
| `EmoteCache.kt` | картинки: скачивание, диск, LRU, декод |
| `Inject.kt` | кнопка в панели ввода + плавающий запасной вариант |
| `PickerUi.kt` | сама панель пикера |
| `Config.kt` | конфиг, общий с приложением-настройкой |
| `SettingsActivity.kt` | настройки и импорт бэкапа расширения |

### Почему хук именно за `TextView.setText`

Классы ВК обфусцированы R8 и переименовываются от версии к версии — модуль,
завязанный на них, ломался бы каждое обновление. Платформенный `TextView`
стабилен, поэтому цепляемся за приватный
`setText(CharSequence, BufferType, boolean, int)`: через него `TextView`
прогоняет вообще все варианты `setText`, включая `setText(int)`.

Панель ввода ищется так же «снаружи»: находим `EditText`, поднимаемся на
пару уровней и берём ряд, где рядом с полем уже висят `ImageView`.

### Что сломает обновление ВК

Не факт обновления сам по себе, а переезд чата на Jetpack Compose: там
`TextView` не используется вообще, и хук перестанет что-либо находить —
молча, без крашей. На этот случай в модуле есть канарейка: через 30 секунд
после старта она пишет в журнал LSPosed, сколько текстов прошло через хук
и сколько подмен сделано. Ноль подмен при живых наборах — повод смотреть,
что изменилось.

Если ВК начал падать — снять галочку в LSPosed и перезапустить. Все хуки
обёрнуты в `try/catch` (`L.safe`), потому что неперехваченное исключение
в чужом процессе роняет не нас, а ВК.

## Сборка

```bash
export JAVA_HOME=/opt/homebrew/opt/openjdk@17
export ANDROID_HOME=/opt/homebrew/share/android-commandlinetools
cd android && gradle assembleDebug
```

APK окажется в `app/build/outputs/apk/debug/`.

Зависимость `de.robv.android.xposed:api` подключена как `compileOnly` —
в APK её классы попадать не должны, реализацию подставляет LSPosed.

## Чего пока нет

- избранное только читается: звёздочку в пикере не нажать, список приезжает
  из бэкапа расширения. Двусторонняя правка требует ContentProvider'а
  в приложении-модуле — процесс ВК в чужие `SharedPreferences` писать не может
- добавление набора по нику стримера (в расширении это резолв через
  api.ivr.fi); здесь пока только ссылка или ID набора
- автозаполнение при наборе текста, как в браузере
