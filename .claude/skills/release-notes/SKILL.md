# Релизы VK7TV

Три артефакта живут в одном репозитории `Spudisis/7tv-vk` и релизятся
раздельно. Не путать их теги, версии и файлы.

| Артефакт | Тег | Заголовок | Версия где | Ассет |
|---|---|---|---|---|
| Расширение (браузер) | `vX.Y.Z` | `[web] X.Y.Z — суть` | `manifest.json` → `version` | `dist/vk7tv-X.Y.Z.zip` |
| Модуль Android | `android-vX.Y.Z` | `[android · ВК + Sova RE] X.Y.Z — суть` | `android/app/build.gradle.kts` → `versionCode`+`versionName` | `vk7tv-module-X.Y.Z.apk` |
| Установщик Android | `installer-vX.Y.Z` | `[installer] X.Y.Z — суть` | `android/installer/build.gradle.kts` → `versionCode`+`versionName` | `vk7tv-installer-X.Y.Z.apk` |

## Пробный канал (dev)

Для сборок, которые надо проверить до общего релиза. Теги другие, релиз
обязательно с `--prerelease`, версия бампится в тех же файлах.

| Артефакт | Тег | Заголовок | Ассет |
|---|---|---|---|
| Модуль | `android-dev-vX.Y.Z` | `[android · dev] X.Y.Z — суть` | `vk7tv-module-X.Y.Z-dev.apk` |
| Установщик | `installer-dev-vX.Y.Z` | `[installer · dev] X.Y.Z — суть` | `vk7tv-installer-X.Y.Z-dev.apk` |

```bash
gradle :installer:assembleDevDebug   # APK: installer/build/outputs/apk/dev/debug/
gh release create android-dev-v0.6.1 dist/vk7tv-module-0.6.1-dev.apk \
  --repo Spudisis/7tv-vk --prerelease --latest=false \
  --title "[android · dev] 0.6.1 — суть" --notes "…"
```

Правила:

- **`--prerelease` обязателен.** Обычный установщик отсеивает пробные релизы
  и по флагу, и по тегу — но полагаться на одну защиту не надо.
- Пробную версию держим **выше** стабильной по semver: пробный установщик
  берёт максимальную версию, и равная стабильная его перебьёт.
- Пробный установщик — отдельное приложение (`com.vk7tv.installer.dev`,
  «VK7TV dev» в лаунчере), стоит рядом с обычным. Обновляет себя только
  пробными релизами; модуль берёт свежайший из обоих каналов.
- Обкатали — выпускаем то же самое обычным релизом под `android-v*` /
  `installer-v*` без `--prerelease`.

## Правила версий (semver)

- **patch** (`X.Y.Z+1`) — фикс, косметика, мелочь.
- **minor** (`X.Y+1.0`) — новая фича.
- **major** — ломающее; пока не было.
- `versionCode` у Android поднимать на 1 при каждой сборке-релизе.
- **Чисто-android изменение НЕ бампит `manifest.json`** расширения: та версия
  показывает, какая сборка *браузерного* расширения у кого стоит, и лишний
  web-релиз только путал бы. У модуля и установщика свои версии.
- Меняешь модуль — **обязательно релизь его** (тег `android-v*`): установщик
  тянет последний модуль с GitHub, иначе поставит старый.

## Заголовок

`[область] X.Y.Z — краткая суть` в нижнем регистре, по-человечески.
Область строго из таблицы: `[web]`, `[android · ВК + Sova RE]`, `[installer]`.
Суть — 2–5 слов, что поменялось для пользователя («иконка 7TV», «превью по
зажатию», «чиним подпись»), а не «фиксы и улучшения».

## Текст описания

Пиши **по-русски, спокойно, без маркетинга**. Не «мы рады представить», а что
именно изменилось и, если это фикс, **из-за чего баг был** — коротко, по делу,
с точки зрения пользователя. Механизм объясняем настолько, чтобы было понятно,
почему теперь иначе; в детали кода не уходим.

Релиз-ноут — это **что изменилось для пользователя**: новые фичи,
исправленные баги (и из-за чего баг был), особенности поведения, и — если
поменялся способ установки/обновления — как теперь ставить. Ничего другого.

**Не писать** про внутреннюю кухню: результаты тестов и сколько их прошло
(«Проверено: 10 из 10»), процесс сборки, рефакторинг «под капотом», который
пользователь не заметит. Это никому в релизе не интересно и только шумит.

Структура:

- Одна вещь — просто абзац-два.
- Несколько — секции `## Заголовок` на каждую.
- Практический хвост, только если он нужен: как ставить/обновлять **если
  способ изменился**, разовые оговорки.
- У Android — как накатывать (если это неочевидно или поменялось): через
  установщик («обновить модуль») или «поставь APK поверх и перезапусти
  клиент через „Остановить"».

Так — хорошо (из v0.11.0):

> ## Широкий эмоут больше не ломает поповер
>
> Очень широкие эмоуты (растяжки, баннеры) включали горизонтальную
> прокрутку. Теперь вписываются в ширину.

Так — плохо:

> ## Улучшения
>
> Исправлены баги и повышена стабильность. Обновляйтесь!

## Коммит

Сообщение коммита в том же духе, с версией впереди:
`vX.Y.Z: …` / `installer X.Y.Z: …` / `module X.Y.Z: …`.
Тело — что и зачем, по-русски. Версию упоминаем всегда (по ней видно, что
у кого стоит). Подпись `Co-Authored-By` как обычно.

## Рецепт выкатки

```bash
# 1. поднять версию в нужном файле (см. таблицу)
# 2. собрать ассет:
#    web:       ./build.sh            → dist/vk7tv-X.Y.Z.zip
#    android:   cd android && JAVA_HOME=…/openjdk@17 ANDROID_HOME=… \
#               gradle :app:assembleDebug   (или :installer:assembleDebug)
# 3. коммит + push в main
# 4. релиз:
gh release create <тег> <путь-к-ассету> --repo Spudisis/7tv-vk \
  --title "[область] X.Y.Z — суть" \
  --notes "…текст по правилам выше…"
```

Только у web-релиза имеет смысл `--latest`; android/installer латестом не
метим, чтобы «Latest» на странице релизов указывал на расширение.

## Подводные камни

- **Установщик подписывать тем же ключом.** Его APK и патчи, которые он
  делает, держатся на постоянной подписи. Собирать релизы установщика надо
  на той же машине (debug-ключ) — иначе у пользователей сломается
  самообновление и «обновить модуль поверх».
- Ассеты класть в `dist/` (он в `.gitignore`, в git не уезжает) и цеплять
  к релизу файлом — в репозиторий бинарники не коммитим.
