# Стиль кода VK7TV

## Комментарии

Комментарий существует ради одного: объяснить **почему так**, когда из кода
это не читается. Механизм, ограничение, причина решения, грабли, на которые
уже наступали. Всё остальное — шум.

**Строго по делу. Никаких метафор, аналогий, образов и «как если бы».**

Плохо (так писать нельзя):

```kotlin
// иначе поездка в метро запомнилась бы как «у стримера нет набора»
// картинки — гости в кэше и уходят первыми
// набор кладётся в тот же ящик, из которого потом достаёт Emotes.load
```

Хорошо:

```kotlin
// 5xx и обрыв связи не кэшируем: это не ответ «набора нет»,
// спросим при следующем запуске
// у картинок не из подключённых наборов приоритет ниже: их вытесняем первыми
// набор пишется в тот же файл кэша, который читает Emotes.load
```

Правила:

- Пиши фактами: что делает код, при каких условиях ломается, чем это
  обусловлено. Без эмоций, шуток и оценок («красиво», «страшный», «магия»).
- Историю правок оставляем только там, где она объясняет решение: «раньше
  было X, ломалось на Y, поэтому Z». Не «улучшили», не «отрефакторили».
- Числа и потолки объясняем: откуда взялось 6 потоков, 40 запросов, 1 ГБ.
- Не пересказывай код словами. `i++ // увеличиваем i` — мусор.
- Язык — русский, как во всём проекте. Строки для пользователя — тоже
  по-русски, без сленга и без сырых HTTP/JSON в тексте ошибки.

## KDoc

Первая строка — что это такое, одним предложением. Дальше, если нужно, —
почему сделано именно так и какие есть ограничения. Тот же запрет на образы.

## Код

- Ничего не должно вылетать наружу из хуков: мы в чужом процессе, любое
  непойманное исключение роняет клиент ВК. Всё рискованное — под `L.safe`.
- Дисковый и сетевой ввод-вывод — только не на UI-потоке.
- Правила подмены эмоутов держим одинаковыми с расширением (`content.js`),
  иначе один и тот же код у разных людей рисуется по-разному.

## README и релиз-ноуты

Факты, а не оправдания: что есть и как работает. «Почему так» живёт в
комментариях к коду, не в README. Про релизы — скилл `release-notes`.
